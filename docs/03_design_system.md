## 2. 상태 표현 규칙 (FR-1204·501·304)

**이 프로젝트에서 가장 중요한 표시 규칙이다.** 스타일이 아니라 데이터 표현 계약이므로
화면·컴포넌트가 바뀌어도 이 4분기는 유지한다.

| 상태 | 표기 | 아이콘 | 색 | 폰트 |
|---|---|---|---|---|
| **수집된 값** | `10.0.1.15` | 없음 | `--fg` | IP·수치 `--mono` / OS·이름 `--sans` |
| **수집 불가** | `수집 불가 — 게스트 도구 미설치` | `⚠` | `--warn-fg` | `--sans` |
| **해당 없음** (하이퍼바이저 미지원) | `해당 없음` | `◌` | `--fg3` | `--sans` |
| **빈 값** | `—` | 없음 | `--fg3` | `--mono` |

**수집 불가일 때 마지막 알려진 값을 병기한다.**

```
⚠ 수집 불가 — 게스트 도구 미설치
   마지막 확인: 10.0.3.42 (3일 전)      ← 10.5px, --fg3
```

상세 화면에서는 이 병기를 `--warn-bg` 배경 + `--warn-line` 테두리 칩으로 강조한다.

**빈칸으로 두지 않는다.** 빈칸은 "IP가 없는 VM"으로 오해되며, 이 구분이 제품의 신뢰도를 결정한다.

### 2.1 게스트 OS 출처 병기 (FR-304)

도구 감지값이 아니라 VM 구성값에서 온 OS는 `(구성값)`을 덧붙인다. 구성값은 실제와 다를 수 있다.

### 2.2 신선도 (FR-502)

수집 후 **24시간 초과**면 `⚠` + `--warn-fg`로 표시한다. 그 이하는 `--fg2`.
목록에는 상대 시각(`3시간 전`), 아래 줄에 절대 시각을 함께 둔다.

### 2.3 전원 상태

| 상태 | 라벨 | 아이콘 | 색 |
|---|---|---|---|
| 실행 중 | `실행 중` | `●` | `--ok` |
| 중지 | `중지` | `■` | `--fg3` |
| 일시 중단 | `일시 중단` | `❚❚` | `--warn-fg` |

### 2.4 연결 상태

| 상태 | 라벨 | 아이콘 | 색 |
|---|---|---|---|
| 정상 | `정상` | `●` | `--ok` |
| 수집 지연 | `수집 지연` | `⚠` | `--warn-fg` |
| 수집 실패 | `수집 실패` | `⚠` | `--danger` |

사유가 있으면 아래 줄에 `--fg3` 10.5px로 병기한다 (예: `인증 정보 만료 — 마지막 성공 이후 재수집되지 않음`).

**색상만으로 상태를 전달하지 않는다.** 아이콘과 텍스트를 항상 함께 쓴다 (FR-1211).

### 2.5 계정 상태 (D-014)

자원의 상태 표현과 **같은 아이콘·색 체계**를 쓴다. 계정용 팔레트를 따로 만들지 않는다.

| 상태 | 라벨 | 아이콘 | 색 |
|---|---|---|---|
| `pending` | 승인 대기 | `◴` | `--warn-fg` |
| `active` | 활성 | `●` | `--ok` |
| `disabled` | 비활성 | `■` | `--fg3` |
| `rejected` | 거부됨 | `✕` | `--danger` |

### 2.6 역할 배지

| 역할 | 라벨 | 표현 |
|---|---|---|
| `admin` | 관리자 | `--kb-soft` 배경 + `--kb-txt` 텍스트 — 권한이 가장 넓으므로 브랜드색으로 눈에 띄게 |
| `operator` | 운영자 | `--chip` 배경 + `--fg2` |
| `viewer` | 조회자 | `--chip` 배경 + `--fg3` |

### 2.7 조회 범위 표시

| 상태 | 표시 |
|---|---|
| 관리자 | `전체` (`--fg2`) |
| 연결 N개 | `연결 2개` (`--fg`) |
| **범위 없음** | **`범위 없음`** (`--warn-fg` + `⚠`) |

**`범위 없음`을 주의색으로 강조한다.** 승인은 됐지만 범위를 못 받은 계정은 로그인해도 화면이 비어 있다.
관리자가 이를 놓치면 "권한이 있는데 아무것도 안 보인다"는 문의로 돌아온다.

## 3. 컴포넌트 규격

Step 1에서 구현한 것만 규격으로 확정한다. 나머지는 캔버스 시안을 참조한다 (§6).

### 3.1 셸 (사이드바 + 헤더)

- 사이드바 234px 고정, `--panel` 배경, 우측 `--line` 경계
- 상단: 26px 앰버 로고(`IV`, `--mono` 11px 700) + 제품명 + `READ-ONLY PORTAL` (10px, `--mono`, `letter-spacing: .08em`)
- 네비 항목: 좌측 3px 활성 바, 활성 시 `--kb-soft` 배경. 우측에 건수(`--mono` 11px, opacity .65)
- **하단 고정 안내문**: "이 포탈은 자원을 조회만 합니다. 전원·스냅샷·리소스 변경 기능은 제공하지 않습니다."
  → **읽기 전용 원칙의 시각적 선언이다. 제거하지 않는다** (FR-1206)
- 테마 토글: 하단, 아웃라인 버튼

### 3.2 데이터 표

- `position: sticky` 헤더, `--panel2` 배경, `z-index: 2`
- CSS Grid 컬럼 고정. 가로 스크롤은 표 컨테이너 내부에서만 발생 (`min-width` 지정)
- 행 hover `--panel2`, 행 구분선 `--line2`
- 셀은 상단 정렬(`align-items: start`) — 2줄 셀과 1줄 셀이 섞이므로
- 이름 셀: 이름(13px/500, 말줄임) + UUID(10.5px `--mono` `--fg3`) 2줄
- 결과 없음: 56px 상하 여백, 중앙 정렬, `--fg3`

### 3.3 배지 · 칩

| 종류 | 규격 |
|---|---|
| 하이퍼바이저 배지 | `--chip` 배경, 좌측에 테두리 태그(`VC`/`HV`, `--mono` 9px 700, radius 2px) + 라벨 |
| 세그먼트 컨트롤 | 1px `--line` 테두리 그룹, 활성 `--kb` 배경 + `--kb-ink` 텍스트 + 600 |
| 표기 규칙 안내 바 | `--panel2` 배경, 1px `--line`, radius 4px — 4분기 범례 |

### 3.4 폼

- 입력: `--panel2` 배경, 1px `--line`, radius 4px, 패딩 `8px 12px`
- 포커스: `border-color: var(--kb)` + `box-shadow: 0 0 0 3px var(--kb-soft)` + `--panel` 배경
- 주 버튼: `--kb` 배경 + `--kb-ink` 텍스트 + 600, hover `filter: brightness(.95)`
- 보조 버튼: 투명 배경 + 1px `--line`, hover 시 `--fg3` 테두리
- 위험 버튼: `--danger` 텍스트 + `--warn-line` 테두리, hover `--warn-bg` 배경

### 3.5 모달

- 오버레이 `rgba(12,10,6,.5)`, 중앙 정렬, 패딩 24px
- 다이얼로그 460px, radius 6px, `0 24px 60px -20px rgba(0,0,0,.5)`
- 제목 15px/700 → 본문 12.5px `--fg2` (`line-height: 1.65`) → 우측 정렬 버튼

### 3.6 읽기 전용 배너

`border-left: 3px solid var(--kb)` + `--panel2` 배경 + 12px `--fg2`.
자원 상세 등 "조작할 것처럼 보이는" 화면에 배치한다.

### 3.7 인증 화면 (로그인·가입)

**셸(사이드바·헤더)이 없다.** 사이드바는 인증된 사용자의 탐색 수단이므로 로그인 전에 노출하지 않는다.

```
  화면 중앙 정렬 · 배경 --bg

        [IV]  가상자원 인벤토리          ← 카드 밖, 상단. 로고 32px
              READ-ONLY PORTAL

  ┌─────────────────────────────────┐    ← --panel, 1px --line, radius 6px
  │  로그인                          │       패딩 26px, --shadow
  │  ┌───────────────────────────┐  │
  │  │ ⚠ 오류 메시지 (있을 때만)  │  │    ← --warn-bg, --warn-line, radius 4px
  │  └───────────────────────────┘  │
  │  아이디                          │
  │  [                            ]  │
  │  비밀번호                        │
  │  [                            ]  │
  │  [        로그인         ]       │    ← 폭 100% 주 버튼
  ├─────────────────────────────────┤    ← --line2 구분선
  │  계정이 없으신가요?  가입 신청    │
  └─────────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 카드 폭 | 로그인 `380px` · 가입 `460px` |
| 카드 패딩 | `26px` |
| 필드 간격 | `14px` |
| 주 버튼 | 폭 100%, 패딩 `10px` |
| 오류 영역 | 폼 단위로 **하나만**. 필드별 오류를 흩뿌리지 않는다 |
| 하단 링크 | `--line2` 구분선 아래, 12px `--fg2` + `--kb-txt` 링크 |

**성공·완료 상태는 폼을 안내 문구로 교체한다.** 가입 접수 후 입력 필드를 남겨두면 다시 제출하게 된다.

### 3.8 사용자 관리 표

승인 대기 영역이 **표 위에 별도 블록**으로 온다. `--warn-line` 테두리 + `--warn-bg` 배경으로 구분하며,
대기가 0건이면 **블록 자체를 렌더링하지 않는다**. 빈 상태를 남겨두면 화면이 상시 경고처럼 보인다.

```
┌ ◴ 승인 대기 3건 ────────────────────────────────────┐
│  kim.dev  김개발  kim@corp.local  2시간 전  [승인][거부] │
└──────────────────────────────────────────────────────┘
```

전체 사용자 표는 §3.2 데이터 표 규격을 그대로 쓴다. 컬럼: 아이디 · 이름 · 역할 · 상태 · 조회 범위 · 마지막 로그인 · 동작.

**위험한 동작의 표현**

| 동작 | 규칙 |
|---|---|
| 비활성화 | 버튼 라벨을 `비활성화`로 한다. `삭제`라고 쓰지 않는다 — 계정은 남는다 (D-014) |
| 마지막 관리자 | 버튼을 `disabled` 처리하고 사유를 `title`로 제공 |
| 본인 계정 | 역할 변경·비활성화 버튼을 **표시하지 않는다** |
| 임시 비밀번호 | 결과를 1회만 보여주는 모달. `--mono` 표시 + 복사 버튼 + "닫으면 다시 볼 수 없습니다" 경고 |

| 검토 항목 | 결과 |
|---|---|
| 조작 UI 요소가 spec에 없는가 (FR-1206) | ✅ **통과** — 전원·스냅샷·복제·리소스 변경·마이그레이션 컨트롤 없음. 삭제는 **포탈의 연결 레코드**에만 있고, 모달이 "하이퍼바이저의 실제 가상 머신은 변경되지 않습니다"를 명시 |
| 수집 불가 / 해당 없음 / 빈 값 구분 (FR-1204) | ✅ **통과** — 4분기가 컴포넌트 규격과 범례로 모두 구현됨. 마지막 알려진 값 병기까지 포함 |
| 상태 색상이 아이콘·텍스트와 함께 정의 (FR-1211) | ✅ 통과 |
| 목록이 서버 페이징 전제인가 (FR-1205) | ⚠ **조정함** — 시안은 전체 로드 + 클라이언트 필터 전제. 구현은 서버 페이징으로 전환 (§5-2) |
| 목 데이터에 실제 서버명·IP가 없는가 (NFR-206) | ✅ 통과 — `corp.local`, RFC1918 대역의 가상 값만 사용 |
| 폰트 조달 | ⚠ **미해결** — CDN 의존. 폐쇄망 배포 시 로컬 호스팅 필요 (§1.3) |

**시안은 읽기 전용 원칙을 정확히 반영했다.** 계획 11 §5.1의 금지 목록이 효과를 냈다.

## 5. 시안 ↔ 구현 차이

시안은 완성 형태(Step 8까지)를 담고 구현은 현재 Step 범위만 다룬다 —
`plans/ROADMAP.md` §10.2 "시안은 넓게, 구현은 좁게" 원칙에 따른 의도된 차이다.

| # | 시안 | Step 1 구현 | 사유 |
|---|---|---|---|
| 1 | 하이퍼바이저 컬럼 (VC/HV) | vCenter만 표시 | Hyper-V는 Step 5 |
| 2 | 전체 로드 + 클라이언트 필터 | **서버 페이징** | FR-1205. 5,000건 전체 로드는 불가 |
| 3 | IP 주소 컬럼 | **미표시** | IP 수집은 Step 4. 값 없이 `—`를 두면 "IP 없는 VM"으로 오해됨 (§2 취지 위반) |
| 4 | 클러스터 · 호스트 (2줄) | 호스트만 (MoRef) | 클러스터·이름 해석은 Step 6 |
| 5 | 헤더 통합 검색 | **미구현** | 검색은 Step 4. 동작하지 않는 입력은 두지 않는다 |
| 6 | 필터 3종 (하이퍼바이저·전원·도구) | **연결 선택만** | 필터는 Step 3~4. 세그먼트 컴포넌트는 연결 선택에 재사용 |
| 7 | VM 상세 화면 · 디스크 · NIC | **미구현** | Step 4 |
| 8 | CSV 내보내기 | **미구현** | Step 8 (감사 로그 연동 필요, NFR-206) |
| 9 | 연결 "설정"(수정) 버튼 | **[지금 수집]으로 대체** | 연결 수정은 Step 3. 수동 수집은 Step 1 필수 기능 |
| 10 | — | **연결 등록 모달 추가** | 시안에 "연결 추가" 버튼만 있고 폼이 없어 §3.4·3.5 규격으로 신규 작성 |
| 11 | 밀도 3단계 prop | 촘촘(9px) 고정 | 설정 화면이 없다. 토큰은 유지 |
| 12 | — | **로그인·가입·사용자 관리 화면 추가** | 시안에 없던 화면. §3.7·3.8 규격으로 신규 작성 (D-014) |
| 13 | — | **사이드바에 사용자 정보·로그아웃·관리자 메뉴 추가** | 인증 도입에 따른 셸 변경. 권한 없는 메뉴는 렌더링하지 않는다 (FR-1213) |

**3·5번이 특히 의도적이다.** 데이터가 없는 컬럼을 빈 값으로 채우거나 동작하지 않는 검색창을 두면
§2의 4분기 규칙이 무의미해진다.
