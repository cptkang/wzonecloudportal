| 확인 사항 | 이 프로젝트에 준 영향 |
|---|---|

| 조직의 10~30%가 소유자 불명 VM이며, 대응은 "문서화된 용도와 실제 사용률 대조" | FR-503(필수 메타데이터 누락 목록)의 우선순위 근거 강화 |

| ServiceNow CMDB의 VM CI는 UUID 기반 식별이 원칙이며, 이름 기반 매칭은 예외 설정으로만 허용된다 | FR-302의 3단계 우선순위 설계가 업계 관행과 일치 |

## 2. 기능 영역 지도

이 포탈이 갖춰야 하는 기능을 13개 영역으로 분해했다. **각 영역이 답하는 질문**이 곧 요건의 목적이다.

| # | 영역 | 답하는 질문 | spec.md | 구현 | 보완 |
|---|---|---|---|---|---|
| 1 | 연결 관리 | 어떤 하이퍼바이저를 보고 있는가 | FR-1xx | 등록·삭제·테스트·수집 | 3건 |

| 3 | 모델 정규화 | 다른 두 제품을 같은 말로 어떻게 부르는가 | FR-3xx | VM 기본 속성 | 3건 |
| 4 | 자원 식별 | 같은 VM을 어떻게 같다고 아는가 | FR-302·303 | 1순위만 | — |
| 5 | 통합 조회·검색 | 찾는 VM에 몇 초 만에 도달하는가 | FR-4xx | 목록 1종 | **5건** |
| 6 | 데이터 품질 | "모른다"를 어떻게 말하는가 | FR-5xx | 게스트 OS만 | **3건** |
| 7 | 포탈 메타데이터 | 이 VM은 누구 것인가 | FR-6xx | 없음 | 1건 |
| 8 | 변경 이력·수명주기 | 무엇이 언제 바뀌었는가 | FR-7xx | 없음 | 1건 |
| 9 | 리포트·내보내기 | 회의에 들고 갈 표를 어떻게 만드는가 | FR-8xx | 없음 | 2건 |
| 10 | 대시보드 | 전체가 지금 어떤 상태인가 | FR-9xx | 없음 | — |
| 11 | 인증·권한·감사 | 누가 무엇까지 볼 수 있는가 | FR-10xx | 전체 구현 | — |

"두 하이퍼바이저가 서로 다른 것을 준다"는 현실이 요건 수준에서 정리되어 있지 않다.
이 두 영역의 실행 계획은 `plans/15-resource-query-revision.md`에 별도로 작성했다.

## 3. 영역별 분석

### 3.1 하이퍼바이저 연결 관리

**핵심 차이**: vCenter는 연결 1개 = 관리 도메인 1개로 규모가 예측 가능하다.
Hyper-V는 연결 1개가 **호스트 1대**(경로 A)일 수도, **fabric 전체 수백 대**(경로 B, SCVMM)일 수도 있다 (D-012).
같은 "연결"이라는 단어가 두 자릿수 규모 차이를 감춘다.

| ID | 구분 | 요건 | 근거 |
|---|---|---|---|
| FR-119 | `[신규]` | **연결 유형 전환 시 중복 경고** — 호스트 직접 연결(경로 A)로 수집하던 호스트가 SCVMM에 편입되면, 같은 VM이 두 연결에서 수집된다. `native_id`가 Hyper-V VM GUID로 동일하므로(계획 05 §8.4) 시스템은 이를 감지할 수 있다. 감지 시 **자동 병합하지 말고 관리자에게 어느 연결을 남길지 묻는다** | D-012, 계획 05 §8.4, FR-308 |
| FR-120 | `[신규]` | **등록 전 수집 규모 미리보기** — 연결 테스트(FR-106) 결과에 조회 가능한 VM·호스트 **개수**를 포함한다. SCVMM 연결 1개로 수천 VM이 들어올 수 있으므로, 등록 시점에 규모를 알아야 수집 주기와 타임아웃을 정할 수 있다 | 계획 05 §7, NFR-104 `[TODO]` |
| FR-121 | `[보완]` | **연결의 수집 경로 표기** — 연결 유형(`hyperv-host`/`hyperv-cluster`/`scvmm`)뿐 아니라 그 경로가 **어떤 속성을 줄 수 있는지**를 연결 화면에 명시한다. 경로 A는 BIOS GUID를 주지만 구성값 OS를 못 주고, 경로 B는 반대다 | `host_mapper.py`·`scvmm_mapper.py` 대조 |

> FR-121의 비대칭은 코드에 이미 존재한다. 경로 A는 `configured_os=None`(Hyper-V에 구성값 OS 개념 없음),
> 경로 B는 `bios_uuid=None`(SCVMM이 BIOS GUID를 주지 않음)이다. 운영자가 "왜 이 VM만 값이 비지"를
> 묻기 전에 화면이 답해야 한다.

### 3.3 모델 정규화 — 두 제품을 같은 말로 부르기

`spec.md` §2.1이 개념 대응표를 제공하지만, **대응되지 않는 것을 어떻게 표현할지**는 UI 요건(FR-1204)에만
있고 데이터 계약 요건이 없다. 리소스풀은 Hyper-V에 존재하지 않고, Datacenter/Folder도 없다.

| ID | 구분 | 요건 | 근거 |
|---|---|---|---|
| FR-309 | `[신규]` | **어댑터 능력(capability) 선언** — 각 수집 경로가 어떤 자원 유형·속성을 제공할 수 있는지 선언하고, 조회 응답이 **"미지원(해당 없음)"과 "지원하나 값 없음"과 "수집 실패"** 를 구분해 내려보낸다. UI가 하이퍼바이저별로 분기해 판단하면 화면마다 규칙이 갈린다 | 계획 03 §3 `ReaderCapabilities`, FR-1204, 상용 도구의 속성 분리 저장 관행 |
| FR-310 | `[신규]` | **단위·기준 통일 규약** — 메모리는 MB, 용량은 바이트, 시각은 UTC 저장·로컬 표시로 통일한다. 하이퍼바이저별 원시 단위가 다르다: SCVMM `Memory`는 MB, Hyper-V `MemoryAssigned`는 바이트, vCenter `memoryMB`는 MB다. 정규화 지점을 어댑터로 못 박지 않으면 세 곳에서 서로 다르게 환산한다 | `scvmm_mapper.py`(MB 직접) vs `host_mapper.py`(`to_mb()` 환산) |
| FR-311 | `[보완]` | **동일 VM 다중 경로 수집 시 우선 경로** — FR-304는 속성 단위 우선순위를 정하지만, 같은 VM을 SCVMM과 호스트 직접에서 동시에 수집하는 경우의 **레코드 단위 우선순위**가 없다. 원칙: SCVMM(주 경로)을 우선하고, 경로 A에만 있는 속성(BIOS GUID·KVP 실시간 값)은 보조로 채운다 | D-012, FR-304, FR-119 |

### 3.4 자원 식별과 중복 방지

`spec.md` FR-302·303, D-006으로 충분하다. **보완 요건 없음.**

### 3.6 데이터 품질 — "모른다"를 말하는 능력

이 포탈의 정체성이 걸린 영역이다. `spec.md` FR-501이 "값 없음 / 수집 불가"의 2분기를 요구하고
FR-1204가 UI 3분기를 요구하는데, 실제로 필요한 것은 **4분기**다.

| 상태 | 의미 | 예 |
|---|---|---|
| 수집된 값 | 값을 확인했다 | `10.0.0.5` |
| 수집 불가 | 값이 있을 텐데 알 수 없다 | 게스트 도구 미설치 → IP·OS |
| 해당 없음 | 개념 자체가 없다 | Hyper-V의 리소스풀 |
| 빈 값 | 확인했고 실제로 없다 | NIC가 0개인 VM |

> **구현 대조에서 발견한 결함**
>
> Hyper-V 어댑터(경로 A·B)는 **이미 게스트 IP를 수집하고 있다** —
> `host_mapper.map_guest_info()`가 KVP `NetworkAddressIPv4`와 `Get-VMNetworkAdapter`의 IP를 병합해
> `GuestInfo.ipv4_addresses`에 채우고, `scvmm_mapper`도 어댑터 IP를 채운다.
> 그런데 `virtual_machines` 테이블에 IP 컬럼이 없고 `vm_repo._to_columns()`도 IP를 담지 않아
> **저장 시점에 전부 버려진다.**
>
> 요건 관점의 의미: FR-404(IP 역조회)는 Hyper-V 측에서 **수집 요건이 아니라 저장·조회 요건**이다.
> Step 4의 IP 작업은 vCenter 수집 추가 + 양쪽 공통 저장 경로 신설로 범위가 갈린다
> (`plans/15-resource-query-revision.md` §4·§5).

|---|---|---|
| CST-11 | `[신규]` | **SCVMM 경로의 게스트 값은 실시간 KVP가 아니라 VMM DB 캐시다.** 게스트 도구를 중지해도 값이 남아 있을 수 있어 "수집 불가" 판정이 늦어진다. 실환경에서 갱신 주기를 실측해야 한다 (조사 노트 §11-12·13) |
| CST-12 | `[신규]` | **경로 A(Hyper-V 호스트 직접)에는 VM 구성값 OS가 없다.** vCenter의 `config.guestFullName` 같은 대체 경로가 없으므로, KVP가 없으면 OS를 전혀 알 수 없다. vCenter와 Hyper-V의 "수집 불가" 발생률이 구조적으로 다르다 |
