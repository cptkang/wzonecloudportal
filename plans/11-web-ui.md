# 11. 포탈 UI

> Wave: 4
> 계층: interface (`static/`)
> 담당 요건: FR-9xx(대시보드), FR-103·109·110(연결 화면), FR-401~409, FR-501·502, NFR-401~404
> 의존: 08
> 관련 결정: D-005, D-007

## 1. 목적

관리자와 사용자가 통합 인벤토리를 조회하고 연결·메타데이터를 관리하는 화면을 제공한다.

**핵심 사용성 원칙 (NFR-401)**: 자원 목록은 하이퍼바이저 종류와 무관하게 **동일한 화면·용어**로 표시한다.
사용자가 "이건 vCenter 자원이라 다르게 봐야 한다"고 느끼면 통합 포탈의 의미가 없다.

## 3. 자원 목록 화면 (FR-401·405·406)

### 3.1 표시 원칙

- vCenter/Hyper-V 자원을 **하나의 표에 동일 컬럼으로** 표시한다
- 하이퍼바이저 종류는 아이콘·배지로만 구분하고, 컬럼 구성을 바꾸지 않는다
- 기본 컬럼: 이름, 전원 상태, IP, 게스트 OS, vCPU, 메모리, 호스트, 연결, 소유자, 신선도
- 표시 컬럼 선택(FR-407)은 사용자별로 저장

### 3.2 "수집 불가" 표시 (FR-501) — 가장 중요한 UI 규칙

`docs/00_research_notes.md` §6: 도구 미설치 VM은 IP·OS를 알 수 없다.
**빈칸으로 두면 "IP가 없는 VM"으로 오해된다.**

| 상태 | 표시 | 스타일 |
|---|---|---|
| 수집됨 | `10.0.0.5` | 일반 |
| 도구 미설치 | `수집 불가 — VMware Tools 미설치` | 주의색 + 아이콘 |
| 도구 미동작 | `수집 불가 — 통합 서비스 미동작` | 주의색 + 아이콘 |
| 상태 불명 | `수집 불가 — 확인 필요` | 주의색 |
| 하이퍼바이저 미지원 | `해당 없음` | 회색 (capability 기반, 계획 03 §3) |
| 실제로 비어 있음 | `—` | 회색 |

**마지막 값 병기**: 도구가 멈춰도 마지막으로 알려진 IP를 보관하므로(계획 12 §2.4),
`수집 불가 (마지막 확인: 10.0.0.5, 3일 전)` 형태로 함께 보여준다. 장애 대응에 유용하다.

사유 문구 매핑을 `GuestInfoAvailability` enum과 1:1로 정의하고 한 곳에서 관리한다.

### 3.3 신선도 표시 (FR-502)

- 최종 수집 시각을 상대 시간으로 (`3시간 전`)
- 임계 초과 시 경고 배지
- **연결 자체가 실패 중이면 자원별 경고가 아니라 상단 배너로** "연결 N개가 수집에 실패하고 있습니다"를 표시한다.
  자원마다 경고를 띄우면 화면이 경고로 뒤덮인다

### 3.4 수명주기 표시

기본 목록은 `active`만 보여준다 (계획 07 §3.3).
필터로 `missing`/`retired`/`disconnected`를 포함할 수 있고, 포함 시 배지로 명확히 구분한다.

## 4. 검색 (FR-403·404)

- 상단 전역 검색창. 입력 형태를 자동 감지 (IP / MAC / 일반 키워드)
- **IP 역조회를 1급 기능으로 노출한다.** 장애 대응 시 최다 사용 시나리오이므로 검색창에 IP를 붙여넣으면 즉시 결과가 나와야 한다
- 결과가 복수면 모두 표시하고 `lifecycle`을 구분 표시 (과거 IP 보유 자원일 수 있음)

## 5. 자원 상세 (FR-402·409)

- `spec.md` §2.2 전체 속성을 그룹별로 표시 (식별 / 스펙 / 게스트 / 네트워크 / 스토리지 / 스냅샷 / 메타데이터)
- **원본 용어 병기 (NFR-402)**: 공통 용어로 표시하되 하이퍼바이저 원본 용어를 함께 보여준다
  - 예: `스냅샷 3개 (Hyper-V 체크포인트)`, `네트워크: VLAN100 (분산 포트그룹)`
- **OS 출처 표시 (FR-304)**: 구성값으로 폴백된 경우 `Ubuntu 22.04 (VM 구성값 — 실제와 다를 수 있음)`
- 관계 탐색(FR-409): 호스트·클러스터·데이터스토어·네트워크를 링크로, 각 대상의 자원 목록으로 이동
- 변경 이력 타임라인 (FR-705): 최근 N건 표시 + 전체 보기

## 6. 연결 관리 화면 (FR-1xx) — 관리자 전용

### 6.1 등록·수정 폼 (FR-103) — 유형별 분기

```
[연결 유형 선택]  ○ vCenter   ○ Hyper-V 호스트   ○ Hyper-V 클러스터   ○ SCVMM(미지원)
       │
       ├─ vCenter 선택 시:  주소 / 포트(443) / 계정(user@vsphere.local) / 비밀번호 / TLS 검증
       │
       └─ Hyper-V 선택 시:  주소 / 포트(5986) / 프로토콜(HTTP·HTTPS)
                            / 인증 방식(NTLM·Kerberos·CredSSP)  ← 필수
                            / 계정(DOMAIN\user) / 비밀번호 / TLS 검증
```

**인증 방식 선택에 도움말을 제공한다** (CST-06). 잘못 고르면 접속 자체가 실패하는데 오류 메시지만으로는 원인을 알기 어렵다.

| 방식 | 도움말 |
|---|---|
| NTLM | 도메인 미가입 호스트 또는 로컬 계정 사용 시. 대상 서버에 TrustedHosts 설정이 필요할 수 있습니다. |
| Kerberos | 도메인 가입 환경에서 도메인 계정 사용 시 권장. |
| CredSSP | **자격증명이 대상 서버로 위임됩니다.** 이중 홉이 필요한 경우에만 사용하세요. |

CredSSP 선택 시 경고 배지를 표시한다 (계획 05 §4).

### 6.2 입력 검증 (FR-104)

- 저장 전 클라이언트 검증 + 서버 422 응답을 **항목별로** 표시
- 주소·포트·계정 형식 오류를 해당 입력란 아래에 표시

### 6.3 비밀번호 취급 (FR-108)

- 수정 화면에서 **비밀번호란은 비어 있고 플레이스홀더로 "변경하려면 입력"** 을 표시
- 비워두면 기존 값 유지됨을 명시
- 어떤 경우에도 기존 비밀번호를 채워 넣지 않는다

### 6.4 연결 테스트 (FR-106) — 단계별 결과 표시

```
✓ 네트워크 도달        hvcluster01.corp.local:5986
✓ TLS 인증서 검증
✗ 인증 실패            계정 또는 인증 방식을 확인하세요
─ 조회 권한            (이전 단계 실패로 미확인)
```

단계별로 보여주는 이유: "접속 불가"와 "인증 실패"와 "권한 부족"은 관리자의 조치가 완전히 다르다.

### 6.5 주소 변경 경고 (FR-110·111)

주소 수정 시 확인 대화상자:

> 주소를 변경합니다. **다른 하이퍼바이저를 가리키게 되면** 다음 수집에서 기존 자원 1,243건이 미발견 처리됩니다.
> 같은 하이퍼바이저의 주소 변경(IP→FQDN, 서버 이전)이라면 문제없습니다.
> **새 하이퍼바이저를 추가하려는 경우 이 연결을 수정하지 말고 새 연결을 등록하세요.**

### 6.6 삭제 (FR-109) — 2단계 확인

```
연결 '본사 vCenter'를 삭제합니다.

영향 범위:  VM 1,243건 · 호스트 18건 · 데이터스토어 42건
처리 방식:  자원은 삭제되지 않고 '연결 해제됨' 상태로 보존됩니다.
            메타데이터와 변경 이력도 유지됩니다.

삭제하려면 연결 이름을 입력하세요: [____________]
```

### 6.7 연결 목록 (FR-113·115)

| 컬럼 | 표시 |
|---|---|
| 표시명 / 유형 / 주소 | |
| 상태 | 정상 / **자격증명 오류** / 접속 불가 / 비활성 |
| 마지막 수집 | 상대 시간 + 성공 여부 |
| 연속 실패 | 횟수 |
| TLS 검증 | 비활성 시 **경고 배지** (FR-115) |

**자격증명 오류 상태를 눈에 띄게 표시한다** (FR-114). 이 상태는 관리자가 자격증명을 갱신해야만 해소되며,
방치하면 그 연결의 데이터가 계속 오래된 채로 남는다.

## 9. 구현 순서

1. 레이아웃·라우팅·로그인 → 검증: 인증 흐름, 토큰 만료 처리
2. 자원 목록 + 필터·페이징 → 검증: vCenter/Hyper-V 동일 포맷 표시
3. **수집 불가 표시** → 검증: 도구 미설치 VM이 빈칸이 아닌 사유로 표시 (Playwright)
4. 전역 검색 + IP 역조회 → 검증: IP 붙여넣기 즉시 결과
5. 자원 상세 + 관계 탐색 + 원본 용어 병기
6. 연결 관리 — 유형별 폼 분기 → 검증: Hyper-V 인증 방식 필수
7. 연결 테스트 단계별 표시
8. 주소 변경 경고 / 삭제 2단계 확인
9. 대시보드 위젯 (`dataviz` 로드)
10. 데이터 품질·변경 이력 화면

## 10. 완료 기준

- [ ] vCenter/Hyper-V 자원이 동일 컬럼 구성으로 표시됨
- [ ] **도구 미설치 VM의 IP·OS가 빈칸이 아니라 "수집 불가 — 사유"로 표시됨**
- [ ] 하이퍼바이저 미지원 항목이 "해당 없음"으로 구분 표시됨
- [ ] IP 붙여넣기로 VM을 즉시 찾을 수 있음
- [ ] Hyper-V 연결 등록 시 인증 방식 선택이 필수이고 도움말이 제공됨
- [ ] 수정 화면에 기존 비밀번호가 표시되지 않음
- [ ] 연결 테스트 결과가 4단계로 구분 표시됨
- [ ] 연결 삭제가 이름 입력 확인을 요구하고 영향 범위를 표시함
- [ ] 자격증명 오류 연결이 목록에서 눈에 띄게 표시됨
- [ ] 대시보드 집계에 조회 범위가 반영됨
- [ ] Playwright E2E 시나리오 8종 통과 (`plans/00-claude-skills-plugins.md` §3.1)

## 11. 주의사항

- **자원을 변경하는 UI 요소(전원 버튼, 삭제 버튼, 스냅샷 조작)를 만들지 않는다.** 이 포탈은 조회 전용이다 (D-005).
  자원 상세의 "삭제"는 존재하지 않으며, 연결 삭제만 있다.
- 빈 값과 수집 불가를 구분하지 않으면 인벤토리 신뢰도가 무너진다 (§3.2). 이 프로젝트에서 UI가 지켜야 할 가장 중요한 규칙이다.
- 경고를 남발하면 무시된다. 연결 단위 문제는 배너로, 자원 단위 문제만 행에 표시한다 (§3.3).
- 대량 목록을 클라이언트에서 전부 로드하지 않는다. 수천 건에서 브라우저가 멈춘다.
