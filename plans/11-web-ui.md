# 11. 포탈 UI

> Wave: 4 · 계층: interface (`static/`)
> 담당 요건: FR-9xx, FR-101~118 화면, FR-401~409, FR-501·502, NFR-401~404
> 의존: 08 · 관련 결정: D-005, D-007

## 1. 목적

관리자와 사용자가 통합 인벤토리를 조회하고 연결·메타데이터를 관리하는 화면을 제공한다.

**핵심 원칙 (NFR-401)**: 자원 목록은 하이퍼바이저 종류와 무관하게 **동일한 화면·용어**로 표시한다.
사용자가 "이건 vCenter 자원이라 다르게 봐야 한다"고 느끼면 통합 포탈의 의미가 없다.

## 3. 자원 목록 화면 (FR-401·405·406)

### 3.1 표시 원칙

- vCenter/Hyper-V 자원을 **하나의 표에 동일 컬럼으로** 표시
- 하이퍼바이저 종류는 아이콘·배지로만 구분. **컬럼 구성을 바꾸지 않는다**
- 기본 컬럼: 이름 / 전원 / IP / 게스트 OS / vCPU / 메모리 / 호스트 / 연결 / 소유자 / 신선도
- 표시 컬럼 선택(FR-407)은 `localStorage`에 사용자별 저장

### 3.2 "수집 불가" 표시 (FR-501) — 가장 중요한 UI 규칙

`docs/00_research_notes.md` §6: 도구 미설치 VM은 IP·OS를 알 수 없다.
**빈칸으로 두면 "IP가 없는 VM"으로 오해된다.**

```javascript
// static/js/format.js
const UNAVAILABLE_LABELS = {
  tools_not_installed: "게스트 도구 미설치",
  tools_not_running:   "게스트 도구 미동작",
  unknown:             "확인 필요",
};

/**
 * 게스트 파생 값(IP·OS·호스트명)의 표시를 결정한다.
 * 빈 값과 수집 불가를 구분하지 않으면 인벤토리 신뢰도가 무너진다.
 */
export function renderGuestValue(guest, field) {
  if (guest.is_collected) {
    const v = guest[field];
    return v ? { text: v, level: "normal" } : { text: "—", level: "muted" };
  }
  const reason = UNAVAILABLE_LABELS[guest.availability] ?? "확인 불가";
  const last = guest[field];
  // 마지막으로 알려진 값을 병기한다 (계획 12 §3.4 — 도구가 멈춰도 이전 값 보존)
  if (last && guest.observed_at) {
    return {
      text: `수집 불가 — ${reason}`,
      hint: `마지막 확인: ${last} (${relativeTime(guest.observed_at)})`,
      level: "warning",
    };
  }
  return { text: `수집 불가 — ${reason}`, level: "warning" };
}

/** 하이퍼바이저가 개념 자체를 지원하지 않는 항목 (계획 03 §3.1) */
export function renderCapabilityValue(supported, value) {
  if (!supported) return { text: "해당 없음", level: "muted" };
  return value ? { text: value, level: "normal" } : { text: "—", level: "muted" };
}
```

| 상태 | 표시 | 스타일 |
|---|---|---|
| 수집됨 | `10.0.0.5` | 일반 |
| 도구 미설치 | `수집 불가 — 게스트 도구 미설치` | 주의색 + 아이콘 |
| 도구 미동작 | `수집 불가 — 게스트 도구 미동작` | 주의색 + 아이콘 |
| 상태 불명 | `수집 불가 — 확인 필요` | 주의색 |
| 하이퍼바이저 미지원 | `해당 없음` | 회색 |
| 실제로 비어 있음 | `—` | 회색 |

**마지막 값 병기**가 실무에서 특히 유용하다. 도구가 멈춰도 마지막 IP를 알면 장애 대응이 가능하다.

### 3.3 신선도 표시 (FR-502)

```javascript
export function renderFreshness(lastSeenAt, quality) {
  const rel = relativeTime(lastSeenAt);        // "3시간 전"
  if (!quality.is_stale) return { text: rel, level: "normal" };
  const reasonLabel = {
    credential_error:    "자격증명 오류",
    connection_failing:  "연결 실패",
    connection_inactive: "연결 비활성",
    resource_missing:    "자원 미발견",
  }[quality.stale_reason];
  return { text: rel, hint: reasonLabel, level: "warning" };
}
```

**연결 단위 문제는 상단 배너로, 자원 단위 문제만 행에 표시한다.**
자원마다 경고를 띄우면 화면이 경고로 뒤덮여 아무도 읽지 않는다.

```
┌─────────────────────────────────────────────────────────────┐
│ ⚠ 연결 2개가 수집에 실패하고 있습니다.                        │
│   본사 vCenter (자격증명 오류) · 지사 Hyper-V (접속 불가)     │
│                                       [연결 관리로 이동 →]   │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 수명주기 표시

기본 목록은 `active`만 보여준다 (계획 07 §3.3).
필터로 포함 시 배지로 명확히 구분한다.

| 상태 | 배지 |
|---|---|
| `missing` | `미발견` (주황) — "N일째 수집되지 않음" |
| `retired` | `폐기` (회색) |
| `disconnected` | `연결 해제됨` (회색) |

## 4. 검색 (FR-403·404)

### 4.1 전역 검색창

상단 고정. 입력 형태를 자동 감지한다.

```javascript
function detectSearchKind(input) {
  const s = input.trim();
  if (isIpAddress(s)) return "ip";
  if (isMacAddress(s)) return "mac";
  if (/^\d{1,3}(\.\d{1,3}){0,3}\.?$/.test(s)) return "ip-prefix";
  return "text";
}
```

**IP 역조회를 1급 기능으로 노출한다** (FR-404). 장애 대응 시 최다 사용 시나리오이므로
검색창에 IP를 붙여넣으면 즉시 결과가 나와야 한다. 별도 메뉴로 숨기지 않는다.

### 4.2 IP 검색 결과

결과가 복수일 수 있다 (분리망 중복, 과거 IP 보유 자원, DHCP 재할당).

```
10.0.0.5 검색 결과 · 2건

┌ web-prod-01        [활성]    본사 vCenter    3시간 전 확인
└ old-web-01         [미발견]  본사 vCenter    12일 전 확인   ← 과거 IP 보유
```

`lifecycle`을 명확히 구분 표시하여 어느 쪽이 현재 사용 중인지 판단할 수 있게 한다.

## 5. 자원 상세 (FR-402·409·705)

### 5.1 섹션 구성

`spec.md` §2.2 전체 속성을 그룹으로 나눈다.

| 섹션 | 내용 |
|---|---|
| 요약 | 이름, 전원, 연결, 신선도, 수명주기 |
| 메타데이터 | 소유자·팀·환경·중요도·용도·태그 (편집 가능 — operator 이상) |
| 게스트 | OS, 호스트명, IP, 도구 상태 (**수집 불가 표시 적용**) |
| 스펙 | vCPU·소켓·코어, 메모리, HW 버전, 펌웨어 |
| 스토리지 | 디스크 목록 (프로비저닝/사용/방식/경로) |
| 네트워크 | 어댑터 목록 (MAC/타입/네트워크/연결) |
| 스냅샷 | 개수, 최신 생성일, 경과일, 총 용량 |
| 소속 | 호스트·클러스터·데이터스토어·네트워크 (링크) |
| 이력 | 최근 변경 타임라인 |

### 5.2 원본 용어 병기 (NFR-402)

공통 용어로 표시하되 하이퍼바이저 원본 용어를 함께 보여준다.

```
스냅샷    3개 (Hyper-V 체크포인트)
네트워크  VLAN100 (분산 포트그룹)
스토리지  CSV-01 (클러스터 공유 볼륨)
리소스풀  해당 없음 (Hyper-V 미지원)
```

### 5.3 OS 출처 표시 (FR-304)

```
게스트 OS   Ubuntu 22.04.3 LTS
게스트 OS   Windows Server 2019 ⓘ VM 구성값 — 실제와 다를 수 있음
```

`os_source`가 `vm_config`면 표시한다. 구성값은 템플릿 생성 시 값이 남아 실제와 다를 수 있다.

### 5.4 관계 탐색 (FR-409)

각 소속 자원을 링크로 만든다. `resource_id`가 `null`이면 (미수집·이름 불일치) 링크 없이 이름만 표시한다.

```javascript
function renderResourceRef(ref) {
  if (!ref) return renderMuted("—");
  if (!ref.resource_id) return renderMuted(`${ref.name} (미수집)`);
  return renderLink(ref.name, `#/resources/${ref.resource_id}`);
}
```

### 5.5 변경 이력 타임라인 (FR-705)

- 시간 역순, 최근 10건 + "전체 보기"
- 사용자 변경과 시스템 변경을 아이콘으로 구분 (`actor` 유무)
- **전원 상태만 바뀐 변경은 기본 접기** (계획 12 §3.5). 토글로 펼침

```
2026-08-05 14:32  시스템   메모리  4096 MB → 8192 MB
2026-08-03 09:15  홍길동   소유자  (없음) → 인프라팀
2026-08-01 22:04  시스템   호스트  esxi-01 → esxi-03
                  [전원 상태 변경 12건 펼치기]
```

### 6.3 입력 검증 (FR-104)

- 클라이언트에서 1차 검증 (형식·필수) + 서버 422 응답을 **필드별로** 표시
- 오류를 해당 입력란 아래에 배치. 상단 요약만 보여주면 어느 항목인지 찾기 어렵다

```javascript
function applyFieldErrors(form, errorResponse) {
  const field = errorResponse.detail?.field;
  if (field) {
    showFieldError(form.querySelector(`[name="${field}"]`), errorResponse.message);
  } else {
    showFormError(form, errorResponse.message);
  }
}
```

### 6.4 비밀번호 취급 (FR-108)

- 수정 화면에서 **비밀번호란은 비어 있고** 플레이스홀더는 `변경하려면 입력`
- 도움말: "비워두면 기존 비밀번호가 유지됩니다."
- **어떤 경우에도 기존 비밀번호를 채워 넣지 않는다.** 서버가 값을 주지 않으므로 채울 수도 없다

### 6.5 연결 테스트 (FR-106) — 단계별 결과

```
연결 테스트 결과

✓ 네트워크 도달        hvcluster01.corp.local:5986        (124ms)
✓ TLS 인증서 검증                                          (89ms)
✗ 인증                 계정 또는 인증 방식을 확인하세요     (1,203ms)
─ 조회 권한            이전 단계 실패로 확인하지 못했습니다
```

**단계별로 보여주는 이유**: "접속 불가"·"인증 실패"·"권한 부족"은 관리자의 조치가 완전히 다르다.
인증 실패면 인증 방식 선택 항목을 강조하여 재검토를 유도한다.

| 주소 | FQDN:포트 |
| 상태 | 정상 / **자격증명 오류** / 접속 불가 / 권한 오류 / 비활성 |
| 마지막 수집 | 상대 시간 + 성공/실패 아이콘 |
| 연속 실패 | 횟수 (0이면 미표시) |
| 자원 수 | VM / 호스트 건수 |
| TLS | 검증 비활성 시 **경고 배지** (FR-115) |
| 작업 | 테스트 · 지금 수집 · 수정 · 삭제 |

**자격증명 오류를 가장 눈에 띄게 표시한다** (FR-114).
이 상태는 관리자가 자격증명을 갱신해야만 해소되며, 방치하면 데이터가 계속 오래된 채로 남는다.

```
⚠ 자격증명 오류  자동 수집이 중단되었습니다. 자격증명을 갱신하세요.  [수정 →]
```

**"지금 수집" 버튼은 자격증명 오류 상태에서 비활성화한다.** 반복 클릭이 계정 잠금으로 이어진다 (CST-05).

## 10. 완료 기준

- [ ] vCenter/Hyper-V 자원이 동일 컬럼 구성으로 표시됨
- [ ] **도구 미설치 VM의 IP·OS가 빈칸이 아니라 "수집 불가 — 사유"로 표시됨**
- [ ] 마지막으로 알려진 값이 병기됨
- [ ] 하이퍼바이저 미지원 항목이 "해당 없음"으로 구분됨
- [ ] 연결 단위 문제가 배너로, 자원 단위 문제만 행에 표시됨
- [ ] IP 붙여넣기로 VM을 즉시 찾을 수 있고 복수 결과가 수명주기로 구분됨
- [ ] 기본 목록에 미발견·폐기 자원이 없음
- [ ] 상세에 원본 용어가 병기됨 (체크포인트, 분산 포트그룹 등)
- [ ] OS 구성값 폴백 시 주의 표시가 나타남
- [ ] Hyper-V 연결 등록 시 인증 방식이 필수이고 도움말이 제공됨
- [ ] CredSSP·HTTP 선택 시 경고가 표시됨
- [ ] 수정 화면에 기존 비밀번호가 표시되지 않음
- [ ] 연결 테스트 결과가 4단계로 구분 표시됨
- [ ] 주소 변경 시 경고 다이얼로그가 나타남
- [ ] 연결 삭제가 이름 입력 확인을 요구하고 영향 범위를 표시함
- [ ] 자격증명 오류 연결의 "지금 수집" 버튼이 비활성화됨
- [ ] 대시보드 집계에 조회 범위가 반영됨
- [ ] Playwright E2E 시나리오 8종 통과

## 11. 주의사항

- **자원을 변경하는 UI 요소를 만들지 않는다** (D-005). 전원 버튼, VM 삭제, 스냅샷 조작이 없다. 자원 상세에는 "삭제"가 존재하지 않으며, 삭제는 연결에만 있다.
- **빈 값과 수집 불가를 구분하지 않으면 인벤토리 신뢰도가 무너진다** (§3.2). UI가 지켜야 할 가장 중요한 규칙이다.
- 경고를 남발하면 무시된다. 연결 단위는 배너, 자원 단위만 행에 (§3.3).
- 대량 목록을 클라이언트에서 전부 로드하지 않는다. 수천 건에서 브라우저가 멈춘다.
- 자격증명 오류 연결에서 수집 버튼을 살려두면 관리자가 계정을 잠글 수 있다 (§6.8).
- 총 건수가 근사치(`total_is_estimate`)면 `약 12,000건`처럼 표시한다.
