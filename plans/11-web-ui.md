# 11. 웹 UI — 디자인 및 구현

> Wave: 0 (시안·디자인 확정) · 4 (구현)
> 계층: interface (`static/`)
> 담당 요건: FR-12xx(웹 UI), FR-9xx(대시보드), FR-101~118 화면, FR-401~409, FR-501·502, NFR-401~407
> 의존: 08 (구현 시) · 관련 결정: D-005, D-007, D-009

## 1. 목적

**웹 브라우저로 접속하는 포탈 화면을 통해 서비스를 제공한다** (FR-1201).
별도 클라이언트 설치 없이 운영자가 브라우저에서 모든 조회·관리를 수행한다.

**핵심 원칙 (NFR-401)**: 자원 목록은 하이퍼바이저 종류와 무관하게 **동일한 화면·용어**로 표시한다.
사용자가 "이건 vCenter 자원이라 다르게 봐야 한다"고 느끼면 통합 포탈의 의미가 없다.

## 2. 이 계획은 두 단계로 나뉜다

| 단계 | Wave | 내용 | 산출물 |
|---|---|---|---|
| **Part A. 디자인** | 0 | Claude Artifacts로 화면 시안 제작 → 검토 → 디자인 토큰 확정 | 시안 Artifact URL, `docs/03_design_system.md` |
| **Part B. 구현** | 4 | 확정된 디자인으로 `static/` 구현 + API 연동 | `static/` |

**Part A를 Wave 0에 두는 이유** (`spec.md` §6): 시안은 백엔드와 병렬 진행할 수 있고,
확정되어야 API 응답 형태(목록에 어떤 필드를 노출할지)를 정확히 정할 수 있다.
구현 후 화면을 고치면 API 변경까지 유발한다.

# Part A. 디자인 (Wave 0)

## 3. Claude 기반 디자인 프로세스 (FR-1212)

```

        ↓
② 검토·피드백      운영팀 담당자가 브라우저에서 직접 조작하며 검토
   같은 파일을 수정해 재게시하면 같은 URL이 갱신된다
        ↓
③ 디자인 확정      토큰·컴포넌트 규격 추출 → docs/03_design_system.md
        ↓
④ 구현 (Part B)    확정된 토큰으로 static/ 구현
```

### 3.1 왜 Artifact로 시안을 만드는가

정적 이미지(피그마 목업, 스크린샷)가 아니라 **실제로 클릭·필터·정렬이 동작하는 화면**이므로,
구현 전에 아래 문제를 발견할 수 있다.

| 시안에서 미리 확인할 것 | 이미지 목업으로는 안 보이는 이유 |
|---|---|
| 목록이 5,000건일 때 페이징·스크롤 체감 | 정적 이미지는 20건만 그린다 |
| **"수집 불가" 표시가 실제로 눈에 구분되는가** (FR-1204) | 한 행만 보면 구분되지만 100행 중에서는 묻힐 수 있다 |
| VM 이름이 60자일 때 컬럼이 깨지지 않는가 | 목업은 짧은 예시 이름만 쓴다 |
| 경고 배지가 여러 개 겹칠 때 읽히는가 (NFR-407) | 실제 데이터 분포를 반영해야 보인다 |
| 다크 모드에서 상태 색상 대비 (FR-1210·1211) | 두 벌을 따로 그려야 한다 |

### 3.2 시안 제작 규칙

**`artifact-design` 스킬을 먼저 로드한 뒤 작성한다.** 페이지 설계 원칙과 시각 언어를 그 스킬이 제공한다.
차트가 포함된 화면(대시보드)은 **`dataviz` 스킬도 함께 로드**한다.

Artifact의 기술 제약과 그 활용:

| 제약 | 시안에서의 의미 |
|---|---|
| 외부 CDN·폰트·이미지 차단 (CSP) | **CSS/JS를 인라인으로 작성 → 그대로 `static/`으로 이관 가능** |
| 단일 페이지 | 화면당 시안 1개. 라우팅은 탭/해시로 흉내 |
| 라이트·다크 자동 대응 필요 | 처음부터 두 테마를 고려하게 되어 FR-1210 누락을 막는다 |
| URL로 공유 (기본 비공개) | 검토자가 링크만으로 접근. 배포 불필요 |

**목 데이터는 실제 데이터 분포를 반영한다.**

```javascript
// 시안용 목 데이터 — 실제 환경에서 나올 수 있는 경계 사례를 반드시 포함한다
const MOCK_VMS = [

  // 도구 미설치 — IP·OS를 알 수 없다 (FR-501). 시안에서 가장 중요한 케이스
  { name: "legacy-db-02", ip: null, os: null, guest: "tools_not_installed" },
  // 도구 미동작이지만 마지막 값 보존
  { name: "batch-worker-07", ip: null, os: null, guest: "tools_not_running",
    lastKnownIp: "10.0.3.42", observedAt: "2026-08-02T09:00:00Z" },

  { name: "prd-seoul-payment-gateway-app-server-node-014", ip: "10.2.11.14", ... },
  // 미발견 자원 — 배지 구분 확인
  { name: "old-web-01", lifecycle: "missing", missingDays: 12, ... },
  // Hyper-V 자원 — 동일 포맷으로 보이는지 (NFR-401)
  { name: "hv-file-01", hypervisor: "hyperv", ip: "10.5.0.9", ... },
];
```

### 3.3 시안 제작 순서

| 순서 | 화면 | 검토 초점 |
|---|---|---|
| 1 | **자원 목록** | 가장 많이 쓰는 화면. 컬럼 구성, 수집 불가 표시, 배지 체계가 여기서 결정된다 |
| 2 | 자원 상세 | 정보 밀도, 섹션 구분, 원본 용어 병기 |
| 3 | 대시보드 | 위젯 배치, 차트 유형·색상 (`dataviz`) |
| 4 | 연결 관리 | **유형별 폼 분기**(FR-103), 인증 방식 도움말, 삭제 확인 |
| 5 | 검색 결과 | IP 역조회 결과의 복수 항목 구분 |

**1번을 먼저 확정한다.** 목록 화면에서 정해진 색상·배지·타이포그래피가 나머지 화면의 기준이 된다.

## 6. 자원 목록 화면 (FR-401·405·406·1203)

### 6.1 표시 원칙

- vCenter/Hyper-V 자원을 **하나의 표에 동일 컬럼으로** 표시 (FR-1203)
- 하이퍼바이저 종류는 아이콘·배지로만 구분. **컬럼 구성을 바꾸지 않는다**
- 기본 컬럼: 이름 / 전원 / IP / 게스트 OS / vCPU / 메모리 / 호스트 / 연결 / 소유자 / 신선도
- 표시 컬럼 선택(FR-407)은 `localStorage`에 사용자별 저장

### 6.2 "수집 불가" 표시 (FR-501·1204) — 가장 중요한 UI 규칙

`docs/00_research_notes.md` §6: 도구 미설치 VM은 IP·OS를 알 수 없다.
**빈칸으로 두면 "IP가 없는 VM"으로 오해된다.**

```javascript
// static/js/format.js
const UNAVAILABLE_LABELS = {
  tools_not_installed: "게스트 도구 미설치",
  tools_not_running:   "게스트 도구 미동작",
  unknown:             "확인 필요",
};

/**
 * 게스트 파생 값(IP·OS·호스트명)의 표시를 결정한다.
 * 빈 값과 수집 불가를 구분하지 않으면 인벤토리 신뢰도가 무너진다.
 */
export function renderGuestValue(guest, field) {
  if (guest.is_collected) {
    const v = guest[field];
    return v ? { text: v, level: "normal" } : { text: "—", level: "muted" };
  }
  const reason = UNAVAILABLE_LABELS[guest.availability] ?? "확인 불가";
  const last = guest[field];
  // 마지막으로 알려진 값을 병기한다 (계획 12 §3.4 — 도구가 멈춰도 이전 값 보존)
  if (last && guest.observed_at) {
    return {
      text: `수집 불가 — ${reason}`,
      hint: `마지막 확인: ${last} (${relativeTime(guest.observed_at)})`,
      level: "warning",
    };
  }
  return { text: `수집 불가 — ${reason}`, level: "warning" };
}

/** 하이퍼바이저가 개념 자체를 지원하지 않는 항목 (계획 03 §3.1) */
export function renderCapabilityValue(supported, value) {
  if (!supported) return { text: "해당 없음", level: "muted" };
  return value ? { text: value, level: "normal" } : { text: "—", level: "muted" };
}
```

| 상태 | 표시 | 토큰 | 아이콘 |
|---|---|---|---|
| 수집됨 | `10.0.0.5` | text | 없음 |
| 도구 미설치 | `수집 불가 — 게스트 도구 미설치` | warning | ⚠ |
| 도구 미동작 | `수집 불가 — 게스트 도구 미동작` | warning | ⚠ |
| 상태 불명 | `수집 불가 — 확인 필요` | warning | ⚠ |
| 하이퍼바이저 미지원 | `해당 없음` | text-muted | 없음 |
| 실제로 비어 있음 | `—` | text-muted | 없음 |

**색상만으로 구분하지 않는다** (FR-1211). 아이콘과 텍스트를 함께 쓴다.

**마지막 값 병기**가 실무에서 특히 유용하다. 도구가 멈춰도 마지막 IP를 알면 장애 대응이 가능하다.

### 6.3 신선도 표시 (FR-502·NFR-407)

```javascript
export function renderFreshness(lastSeenAt, quality) {
  const rel = relativeTime(lastSeenAt);
  if (!quality.is_stale) return { text: rel, level: "normal" };
  const reasonLabel = {
    credential_error:    "자격증명 오류",
    connection_failing:  "연결 실패",
    connection_inactive: "연결 비활성",
    resource_missing:    "자원 미발견",
  }[quality.stale_reason];
  return { text: rel, hint: reasonLabel, level: "warning" };
}
```

**연결 단위 문제는 상단 배너로, 자원 단위 문제만 행에 표시한다** (NFR-407).
자원마다 경고를 띄우면 화면이 경고로 뒤덮여 아무도 읽지 않는다.

```
┌─────────────────────────────────────────────────────────────┐
│ ⚠ 연결 2개가 수집에 실패하고 있습니다.                        │
│   본사 vCenter (자격증명 오류) · 지사 Hyper-V (접속 불가)     │
│                                       [연결 관리로 이동 →]   │
└─────────────────────────────────────────────────────────────┘
```

## 7. 검색 (FR-403·404)

### 7.1 전역 검색창

```javascript
function detectSearchKind(input) {
  const s = input.trim();
  if (isIpAddress(s)) return "ip";
  if (isMacAddress(s)) return "mac";
  if (/^\d{1,3}(\.\d{1,3}){0,3}\.?$/.test(s)) return "ip-prefix";
  return "text";
}
```

**IP 역조회를 1급 기능으로 노출한다** (FR-404). 장애 대응 시 최다 사용 시나리오이므로
검색창에 IP를 붙여넣으면 즉시 결과가 나와야 한다. 별도 메뉴로 숨기지 않는다.

### 7.2 IP 검색 결과

결과가 복수일 수 있다 (분리망 중복, 과거 IP 보유 자원, DHCP 재할당).

```
10.0.0.5 검색 결과 · 2건

┌ web-prod-01        [활성]    본사 vCenter    3시간 전 확인
└ old-web-01         [미발견]  본사 vCenter    12일 전 확인   ← 과거 IP 보유
```

## 14. 주의사항

- **자원을 변경하는 UI 요소를 만들지 않는다** (FR-1206, D-005). 전원 버튼, VM 삭제, 스냅샷 조작이 없다. 자원 상세에 "삭제"가 존재하지 않으며, 삭제는 연결에만 있다.
- **빈 값과 수집 불가를 구분하지 않으면 인벤토리 신뢰도가 무너진다** (§6.2). UI가 지켜야 할 가장 중요한 규칙이다.
- 경고를 남발하면 무시된다. 연결 단위는 배너, 자원 단위만 행에 (§6.3).
- 대량 목록을 클라이언트에서 전부 로드하지 않는다.
- 자격증명 오류 연결에서 수집 버튼을 살려두면 관리자가 계정을 잠글 수 있다 (§9.8).
- **시안을 그대로 배포하지 않는다.** Artifact는 검토용이며, 실제 서비스는 인증·API 연동이 있는 `static/`이다.
- 시안의 목 데이터에 실제 서버명·IP를 쓰지 않는다. Artifact URL이 공유될 수 있다.
